# 追加の条件 3: 停滞の率は打鍵の量を数えているか（計算の前にコミットする）

- 日付: 2026-11-07。主の条件（08010482）・長さ（6df7bde6）・区間と得点（b5687936）への追加。どれも変えない。
- 理由: 外枠の attack-me round 2（[internal reference removed]）で R1 が、本人の分位の θ では停滞の率が打鍵の量（流暢さ）に比例する成分を持ち、KLiCKe の得点との関連の符号がそれで説明できるかもしれないと指摘した（固定 θ の負は遅い書き手の長い間隔で説明できる）。研究者が計算で確かめると決めた（[internal reference removed]）。
- 見たもの: 89 通りの得点との関連（`round1_extra.json`）とその族・窓ごとの内訳（notes の追加の計算 2）。押下の率と停滞の率・得点の関係は見ていない。

## 量

- 書き手の押下の率: KLiCKe の各書き手で、replay の観測区間（基準の定義の区間）の中の押下の数（文字・削除・ほかのすべて）/ 観測区間の長さ（時間）。定義によらない 1 つの値。
- 各通りで:
  - P1 書き手の停滞の率と押下の率の Spearman の順位相関（`round1_extra.py` と同じ書き手・同じ停滞の率）。
  - P2 得点と停滞の率の、押下の率を固定した偏順位相関（3 つを順位に変えた Pearson の偏相関）。区間は書き手を単位にした再標本（2,000 回・SEED）。
- 参照: 得点と押下の率の Spearman（定義によらない 1 つの値・区間つき）。
- 速さの記述（R1 の 2 つ目の指摘）: CS1 2019 と CS1 2021 で、書き手ごとの隣り合う押下の間隔の中央値（観測区間の中・2 秒未満の間隔に限る）の、書き手の間の中央値と四分位。KLiCKe と CoAuthor も同じに出す。

## 読み方（先に置く）

- R1 の機構が支持される: 本人の分位の族で P1 の中央値が +0.3 以上、かつ P2 で区間が 0 を含まず正の通りが 0 になる（現在の 10 から）。このとき外枠の C1 は「族によって停滞の率は打鍵の量にも遅さにも寄る量になり、得点との関連の符号はそれに従う」と書く。
- 支持されない: P2 で区間が正の通りが残る、または P1 の中央値が +0.3 未満。このとき「押下の率を固定しても符号の入れ替わりが残る」と書く。
- どちらでもない場合（P1 は高いが P2 の正が一部残る）は、両方の値を並べて書く。
- 偏相関の 89 通りの範囲・区間で負・正・0 を含む数を、元の相関の数と並べて報告する。

## 確かめ

- 対照: P2 の作り方で、押下の率の代わりに停滞の率そのもの（にごく小さな揺れを足したもの）を固定すると偏相関が 0 近くになること、関係の無い乱数を固定すると元の相関とほぼ同じになることを selftest で確かめる。
- 元の相関（`round1_extra.json` の rho）を同じ書き手で再現する（小数 6 桁）。
- 出すのは集計値だけ（相関・区間・数・分位）。書き手ごとの値・ID・本文は出さない。
