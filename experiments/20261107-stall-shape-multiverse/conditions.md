- 検証する仮説: 該当なし（記述と multiverse・検定で判定しない）。単独にするかの基準（§J）だけを先に置く。基準は研究者の判断の材料で、判断そのものではない。
- 出典: KLiCKe [internal reference removed]（利用条件 [internal reference removed]）・CoAuthor [internal reference removed]・CS1 [internal reference removed]。停滞の定義は [internal reference removed] と [internal reference removed] の既定（論文 1 の付録の定義と同じ）。

## D データと単位

| データ | 使う書き手 | 単位の階層 | 作業場 |
|---|---|---|---|
| KLiCKe | 観測 10 分以上の書き手（見た 3,434 人＋論文 1 で開けた 1,498 人） | 書き手（作文 1 本） | `klicke/work` |
| CoAuthor | 見た 41 人（取り置きの 18 人は作業場に無い・開けない） | 書き手 > セッション | `landscape/coauthor_work` |
| CS1 2019 | 見た書き手＋論文 1 で開けた 146 人 | 書き手 > 課題 > 日 > 作業のまとまり（課題は書き手をまたいで共通の効果も持つ） | `cs1/work2019`・`cs1/work2019_holdout` |
| CS1 2021 | 見た 31 人（取り置きの 13 人は開けない） | 同上 | `cs1/work2021_seen` |

- D1 作業のまとまり（CS1）は作業場の `blocks`（30 分の空白で切った押下のまとまり）。日は、同じ課題の中で、まとまりの間の空白が 6 時間以上のところで切った続き（時刻帯が分からないので暦の日を使わない）。
- D2 課題の識別（CS1）: 作業場の番号は (SubjectID, AssignmentID) の並びの順なので、生の CSV の 2 列から同じ並びを作り直し、書き手の SHA-256（`writers.json`）で照合して、番号 → 課題の通し番号を作る（ID は repo に書かない）。照合が合わない単位があれば止める。
- D3 取り置きの照合: 作業場の `build_summary.json` の `holdout_sha256` が、`cs1/holdout.json`（見た側）・`cs1/skip_seen_2019.json`（開けた 146 人の側）・`cs1/skip_holdout_2021.json`（2021 の見た側）と一致することを確かめ、違えば止める。CoAuthor は作業場の書き手が `landscape/holdout.json` の 18 人と交わらないこと（`sessions.json` の番号では照らせないので、作業場の作り方の要約 `held_out_sessions` = 288 を確かめる）。
- D4 露出: 単位の観測時間 = 観測区間（`observed_intervals`）の長さの和。CS1 のまとまり・日は、観測区間をまとまりの [最初の押下, 最後の押下] で切った長さ。停滞は t0 の時刻で単位に割り当てる。観測 5 分未満の単位は件数の計算から外す（数を報告する）。
- D5 長さ: 再開した停滞の t0 から次の文字の入力まで（秒）。再開しなかった停滞は長さの計算から外し、数を報告する。分析は対数。

## B 基準の定義（B0）

replay の既定と同じ: 窓 W = 30 秒、条件 A =（窓の文字の押下 − 削除の押下）< 1、θ = 単位の中の隣り合う押下の間隔の nearest-rank 0.99 分位（100 個から・因果に累積）、観測区間は作業場の `observed_intervals`。K1 の照合で、B0 の始まりが全単位で replay と一致することを確かめる。

## C1 揺れの分解

- 件数: ポアソン対数正規の混合モデル。log λ = μ + log(露出) + 書き手 + 課題（書き手の中）+ 日（課題の中）+ まとまり（日の中）＋ 課題の共通の効果（交差）。CS1 の 2 年版それぞれ。CoAuthor は書き手 + セッション。KLiCKe は書き手の 1 水準しかないので C1 に入れない（C2 だけ）。
- 推定: statsmodels の `PoissonBayesMixedGLM`（変分ベイズ）。分散成分の事後平均と、各水準の分け前（その水準の分散 / 潜在の分散の和）。
- 長さ: 対数の長さの線形混合モデル（書き手 + 課題 + 日 + まとまり + 停滞の残差）。statsmodels の `MixedLM`（REML・書き手を群・下の水準を分散成分）。
- K5 の回復の確かめ（推定の前に通す）: 同じ単位の構造と露出で、既知の分散成分（各水準 SD 0.3 と、書き手 0.5・ほか 0.2 の 2 組）から件数と長さを模擬し、推定が SD を ±30% 以内で戻すかを見る。戻さない水準は、分け前を報告しても判定（§J）に使わない。

## C2 数え上げとの比（過分散）

- 各データ・各単位の水準（KLiCKe: 書き手／CoAuthor: セッション・書き手／CS1: まとまり・日・課題・書き手）で、Pearson の分散の指数 φ = Σ (n − ê)² / ê ÷ (k − p)。
  - ê の 2 つの基準: (a) 全体で 1 つの率 × 露出（p = 1）、(b) 書き手ごとの率 × 露出（書き手より下の水準だけ・p = 書き手の数）。(b) が「同じ人の中の揺れが数え上げを超えるか」。
- 区間: 書き手を単位にした再標本（2,000 回・SEED）。
- 俯瞰の L5（SD の比）は書き手の課題 5 つ以上に絞っていた。C2 は絞らない（露出 5 分以上の単位を全部）。

## C3 multiverse

- 振るもの（90 通り）:
  - 窓 W: 15・30・60 秒
  - θ: 本人の分位 0.95・0.99・0.995（100 個から）／固定 10 秒・30 秒（本人によらない）
  - 条件 A: 正味（文字 − 削除）< 1 ／ 文字の押下 < 1（削除を数えない）
  - 観測区間の切り方: replay の観測区間 ／ 押下の空白 5 分で切る ／ 押下の空白 30 分で切る（押下で切る区間は [最初の押下, 最後の押下]）
- 各通り・各データで出すもの: 停滞の 1 時間あたり（全体の率と、書き手の率の中央値）、長さの中央値、C2 の φ（(a) と (b) の主の水準: KLiCKe 書き手・CoAuthor セッション・CS1 まとまりと課題）、停滞が 0 件の書き手の割合、B0 とのラベルの一致（B0 の停滞の t0 のうち、その通りの停滞の [s, 再開] に入る割合と、その逆の割合）、4 つのデータの率の順位。
- C1 の分解は、W × θ の分位の 9 通り（条件 A と切り方は既定）でだけ回す（計算の重さ）。
- C3b 推定の水準を切り方で揃える: 作業場の `feat` の行（1 秒ごとの `p_stuck`）のうち、最後の押下からの経過が 30 秒・60 秒・180 秒以内の行だけで `p_stuck ≥ 0.60` の時間の割合（書き手の中央値）を出し、全部の行の値と並べる。CS1 と KLiCKe の比が、揃えるとどれだけ縮むか。

## K 確かめ（計算の前に通す）

- K1 B0 の照合: 全単位で Python の始まりの (s, t0) の組が replay と一致する。CS1 2019 の見た側では、作業場の変種（`work2019_w15`・`work2019_w60`・`work2019_q995`）とも、同じ設定の Python が一致するかを見る（変種の作り方が違えば一致しないことがあり、その場合は数と理由を報告して先へ進む）。
- K2 陽性対照: 合成の押下列（停滞が 1 件ある・無い・削除の連打で立つ）で、各設定が見込みどおりの件数を出す。
- K3 変異: 条件 A の不等号・θ の分位・区間の切り方を壊すと K1 か K2 が赤になる。
- K4 D2・D3 の照合が通る。
- K5 回復（C1）。

## J 単独にするかの基準（研究者の判断の材料）

次の 3 つを数える。

- M（分析者の切り方で結論が動く）: 次のどれかが成り立つ。
  - M1 4 つのデータの停滞の率（全体の率）の順位が、B0 と違う通りが 90 通りの 25% 以上。
  - M2 C2 の (b) の φ が 1.5 以上か未満かの結論が、主の水準のどれかで、90 通りの 25% 以上で B0 と逆になる。
  - M3 C3b で、CS1 2019 と KLiCKe の `p_stuck ≥ 0.60` の割合の比が、60 秒以内の行に揃えると全部の行の比の半分以下になる。
  - M4 B0 とのラベルの一致（両方向の小さい方）が 0.5 未満の通りが 25% 以上あり、かつその中に B0 と率が ±20% 以内の通りがある（率が似ていても指す時刻が違う）。
- V（人より下の水準が効く）: CS1 のどちらかの年版で、件数の分解の、書き手より下の水準（課題・日・まとまりの和）の分け前が書き手の分け前を超える（K5 で回復した水準だけで）。
- O（同じ人の中で数え上げを超える）: C2 の (b) の φ が、CS1 のまとまりか課題、CoAuthor のセッションのうち 2 つ以上で 1.5 以上（区間の下端が 1 を超える）。

推奨の規則: M が成り立ち、V か O のどちらかが成り立てば「単独にする」を推奨する。M が成り立たず V と O が成り立てば「論文 1 の改訂か論文 3 の補足に回す（ラベルは切り方に頑健という記述は補足で十分）」を推奨する。どれも成り立たなければ見送りを推奨する。推奨は研究として強いかで決め、最後は研究者が決める（AskUserQuestion）。

## 言えないこと（先に書く）

- 停滞の始まりは詰まりの判定ではない（[internal reference removed]）。どの定義が「正しい」かは言えない（本人の申告が無い）。
- データの間の違いは、作業の種類・記録の仕方・単位の長さが同時に違う。C3 は切り方を揃えるが、作業の違いを分けるのではない。
- CS1 の日は 6 時間の空白で切った推定。課題の共通の効果は題材と難しさと順番を分けない。
- 変分ベイズの分散成分は過小になりうる（K5 で大きさを確かめる）。
